### 1. What the Microphone Actually Gives You

The CoreS3's onboard microphone doesn't hand you a single "volume"
number the way the IMU hands you a clean `(ax, ay, az)` tuple. It
hands you **raw audio** — a buffer of digitized sound pressure
samples, captured over I2S, the same kind of hardware interface used
by the camera's image sensor. Getting a usable number out of it takes
one extra step that the IMU didn't need: **you decide what "loud"
means by measuring the buffer yourself.**

The whole flow, matching the official microphone example this course
builds on:

```python
Mic.begin()
rec_data = bytearray(1024)      # a buffer to record into
Mic.record(rec_data, 16000, False)   # start recording, non-blocking
while Mic.isRecording():
    time.sleep_ms(5)
# rec_data now holds one buffer's worth of raw PCM audio
```

- **`Mic.begin()`** starts the microphone hardware. Call it once in
  `setup()`, the same way you called `M5.Imu` implicitly just by
  reading it — except the mic must be explicitly started and stopped.
- **`Mic.record(rec_data, rate, stereo)`** launches a recording into
  the buffer you supply. `rate` is the sample rate in Hz (8000, 11025,
  16000, 22050, 32000, or 44100 are typical); `stereo` is `False` for
  this course. Recording happens in the background — the call returns
  immediately.
- **`Mic.isRecording()`** returns `0` once the buffer is full. The
  short `while` loop above simply waits for that buffer to finish.

> **Gotcha — the mic and the speaker cannot run at the same time.**
> Both use the same underlying I2S hardware peripheral. If your
> program (or a later lab) ever plays audio, call `Speaker.end()`
> before `Mic.begin()`, and vice versa. Lab 6 doesn't touch the
> speaker, but the moment a future lab does, this ordering matters.

### 2. From a PCM Buffer to a Single Number

`rec_data` is a raw `bytearray` — bytes, not sound-level numbers. Each
audio sample recorded by the CoreS3's microphone is a **16-bit signed
integer**, stored as two consecutive bytes. Turning it into something
an `M5LED` can react to means unpacking those bytes and picking a
single value that represents "how loud was this buffer."

```python
import struct

def peak_amplitude(buf):
    """Return the largest absolute sample value found in a raw
    16-bit signed PCM buffer."""
    sample_count = len(buf) // 2
    samples = struct.unpack("<%dh" % sample_count, buf)
    peak = 0
    for s in samples:
        if abs(s) > peak:
            peak = abs(s)
    return peak
```

- **`struct.unpack("<%dh" % n, buf)`** reads `n` little-endian
  (`<`), signed 16-bit (`h`) values out of the buffer in one call —
  the standard MicroPython way to turn raw bytes into numbers.
- A 16-bit signed sample ranges from **-32768 to 32767**. Silence
  hovers near `0`; a loud sound pushes the sample far from `0` in
  either direction — which is why the function above tracks the
  **absolute value**, not the raw signed sample.
- **Peak, not average.** A single very loud spike (a clap, a knock on
  the desk) should visibly register even in a short buffer. Averaging
  the whole buffer would smooth that spike away. This course always
  uses **peak amplitude** for exactly this reason — it's also the
  simpler, more gradable definition.

> **If `struct.unpack` raises an error about buffer size,** your
> buffer's byte length isn't an exact multiple of 2 (one 16-bit sample
> is 2 bytes). Always size recording buffers as an even number of
> bytes — `bytearray(1024)` is safe; `bytearray(1023)` is not.

### 3. Clamp-and-Scale, Again

A raw peak amplitude is an integer somewhere in `0`–`32767`. That's
already a bounded range, which makes this the **easiest** clamp-and-
scale you've done yet — but the pattern is identical to Lecture 4's
accelerometer-to-bar conversion, and to Lecture 3's slider-driven
formula before that:

```python
def clamp(value, low, high):
    if value < low:
        return low
    if value > high:
        return high
    return value

def amplitude_to_percent(peak, noise_floor=200, loud_ceiling=12000):
    peak = clamp(peak, noise_floor, loud_ceiling)
    fraction = (peak - noise_floor) / (loud_ceiling - noise_floor)
    return int(fraction * 100)
```

Two choices worth noticing, because Lab 6 asks you to make the same
kind of choices explicitly and defend them in your comments:

- **`noise_floor`** absorbs the microphone's own electrical noise and
  quiet-room background hiss, so a silent room reads close to `0%`
  instead of some jittery small number.
- **`loud_ceiling`** is the peak amplitude you're treating as "100%
  loud" — chosen empirically by testing on your own physical device,
  not a value you can derive from a datasheet. This is the same
  "pick a sensible full-scale range and defend it" decision Lecture 4
  made with `±1.0 g` and `±0.5 g` for Normal and Sensitive tilt modes.

### 4. `M5LED` — a Simulated Indicator Light

`M5LED` is a lightweight widget that draws a coloured circular
indicator — visually it's simple, but it's the first widget this
course has used that's driven by **three independent properties**
(on/off state, colour, and brightness) instead of just one value.

```python
led0 = m5ui.M5LED(
    x=135, y=40, size=60,
    color=0x00FF00, on=True,
    parent=page0,
)
```

| Constructor argument | Meaning |
|---|---|
| `x`, `y` | Top-left position, same as every other widget |
| `size` | Width **and** height in pixels — `M5LED` is always square |
| `color` | RGB888 colour, same format as every other widget's `color`/`text_c` |
| `on` | Initial state — `True` lights it, `False` leaves it dark |
| `parent` | The page it belongs to, same as always |

Once built, `M5LED` exposes exactly the controls you'd expect from a
real indicator lamp:

```python
led0.on()                   # turn it on
led0.off()                  # turn it off
led0.toggle()                # flip its current state
led0.set_color(0xFF0000)     # change colour (RGB888)
led0.set_brightness(75)      # 0-100, mapped internally to a usable range
brightness = led0.get_brightness()   # read it back, 0-100
```

`set_brightness()` takes a single 0–100 integer — the widget handles
the internal remapping to its actual display range for you. That
makes it a **direct drop-in target** for the 0–100 output of
`amplitude_to_percent()` above: no widget-specific scaling step
needed, unlike `M5Bar`/`M5Slider`, which needed their own
`min_value`/`max_value` handled separately.

> **`M5LED` has no `VALUE_CHANGED` event.** Like `M5Bar`, it's a
> **display-only** widget — nothing about it responds to touch, so it
> needs no `add_event_cb` registration at all. You'll drive it
> directly from `loop()`, exactly like the tilt bar in Lecture 4.

### 5. Same Shape, New Sensor: Mic-Driven LED in `loop()`

Putting it together follows the poll-driven pattern from Lecture 4
§5 exactly — read the sensor, run it through clamp-and-scale, push
the result into the widget, every single pass through `loop()`:

```python
def loop():
    M5.update()
    Mic.record(rec_data, SAMPLE_RATE, False)
    while Mic.isRecording():
        pass
    peak = peak_amplitude(rec_data)
    percent = amplitude_to_percent(peak)
    led0.set_brightness(percent)
```

This is the same three-line shape as `tilt_bar.set_value(accel_to_bar(ax), ANIM_OFF)`
from Lecture 4 — read sensor, clamp-and-scale, push to widget — with
the microphone and `M5LED` standing in for the IMU and `M5Bar`. The
underlying skill you're practicing is the same one, applied to a
third sensor.

> **Gotcha — recording inside `loop()` takes real time.** Unlike an
> IMU read, which returns instantly, a `Mic.record()` call takes
> roughly `buffer_size / sample_rate` seconds to fill — a short buffer
> (e.g. 1024 bytes at 16000 Hz, well under a tenth of a second) keeps
> the LED feeling responsive; a buffer sized in whole seconds will
> make the LED update sluggishly and can make a touch-driven switch
> feel unresponsive too, since nothing else in `loop()` runs while the
> recording finishes. Keep recording buffers short, the same way
> Lecture 4 required cheap work inside every `loop()` pass.

### 6. Detecting Words with Silence Gaps

Everything so far measures "how loud right now." A different, equally
useful question is "how many separate sounds have happened" — for
example, counting spoken words. The microphone can't tell you that
directly either; like peak amplitude, it's something you compute
yourself, this time by watching for **pauses**.

The idea: a "word" is any stretch of non-silent audio that follows a
**confirmed pause** of some minimum length. The tricky part is
deciding what counts as "confirmed" — a real spoken pause between
words is typically a quarter-second or more, nowhere near instant, so
this can't be judged from a single buffer. It has to be tracked across
**several consecutive `loop()` passes**.

**Step 1 — Decide how many consecutive silent passes make a real
gap.** If one buffer takes about 32ms (1024 bytes at 16000 Hz, as
established in §5), and you want to treat roughly a quarter-second of
silence as a genuine pause between words:

```python
BUFFER_MS = 32
GAP_MS = 250
GAP_PASSES = round(GAP_MS / BUFFER_MS)   # 8 passes, ~256ms
```

`GAP_PASSES` won't land on the target exactly, since a real buffer
duration rarely divides evenly into a round number of milliseconds —
that's expected, and close enough for this to work reliably.

**Step 1b — Pick a threshold for "loud enough to be a word," separate
from your level meter's noise floor.** It's tempting to reuse the
`noise_floor` from §3 to decide "silent vs. not," but that threshold
was only ever chosen to mean "treat this as 0% on the level meter" —
it sits close to the microphone's own electrical noise. Ordinary
ambient sound — a chair creak, HVAC hum, someone talking across the
room — is often louder than that noise floor while still being far
quieter than an actual word spoken at the mic. Reusing `noise_floor`
here means a quiet room's background hum can register as spoken
words. The fix is a **second, stricter constant**, chosen the same
empirical way as every ceiling in this course:

```python
WORD_AMPLITUDE_THRESHOLD = 1500   # tune this on your own hardware
```

**Step 2 — Track three small pieces of state across `loop()` passes:**
how many consecutive quiet passes have just happened, whether a word
is currently "in progress," and the running total.

```python
silent_run = 0
in_word = False
word_count = 0
```

This is the same "module-level flag that persists between passes"
approach used for the switch's `flipped` tracking in Lab 4 — nothing
new about *how* the state is stored, just what it's tracking.

**Step 3 — Advance the state machine by one buffer's peak amplitude,
every `loop()` pass:**

```python
def update_word_count(peak):
    global silent_run, in_word, word_count

    if peak < WORD_AMPLITUDE_THRESHOLD:
        silent_run += 1
        if silent_run >= GAP_PASSES:
            in_word = False
    else:
        if not in_word:
            word_count += 1
            in_word = True
        silent_run = 0

    return word_count
```

Walk through what each branch is doing:

- **A buffer below `WORD_AMPLITUDE_THRESHOLD`** extends `silent_run`.
  If enough *consecutive* quiet buffers pile up to reach `GAP_PASSES`,
  the pause is confirmed real, and `in_word` is cleared — the meter is
  now genuinely "between words," not just caught a brief dip.
- **A buffer at or above the threshold while `in_word` is already
  `True`** means we're still inside the same word — nothing is
  counted again, `silent_run` resets to zero since the streak of quiet
  broke.
- **A buffer at or above the threshold while `in_word` is `False`** is
  the important case: this is the very first sound *after* a confirmed
  pause — the start of a genuinely new word. That's the one moment
  `word_count` increments.

> **Why this doesn't get fooled by a brief mid-word dip.** A stop
> consonant or a quick catch of breath can drop the signal below
> `WORD_AMPLITUDE_THRESHOLD` for a pass or two without `silent_run`
> ever reaching `GAP_PASSES`. Because the count only increments on the
> transition *out of a confirmed gap*, a dip that never reaches the
> full threshold never clears `in_word`, so it can never trigger a
> second increment for what is still, acoustically, one continuous
> word.

> **Why this doesn't get fooled by ambient noise, either.** Because
> the threshold is `WORD_AMPLITUDE_THRESHOLD` rather than the level
> meter's `noise_floor`, background sound that would already register
> as a nonzero percentage on the level meter can still correctly stay
> below the word-detection bar. The two thresholds answer two
> different questions — "how loud is it right now" versus "is this
> loud enough to plausibly be a spoken word" — and conflating them was
> an early mistake worth calling out explicitly, since it's an easy
> one to make.

> **This is not a transcription system.** Fast, naturally connected
> speech often has little or no real pause between words — this
> technique only reliably counts words that are separated by an
> actual, audible gap. It's the right tool for deliberately paced
> speech (reading aloud, counting, practicing a rehearsed line slowly)
> and the wrong tool for judging fluent conversational speech word-
> for-word. Knowing the limits of a measurement is as important as
> building it — this is the same honesty this course has applied to
> every clamp-and-scale ceiling choice so far.

### 7. Building a Gradient Meter Out of `M5LED`

A single round `M5LED` tells you "how loud" through brightness alone.
A more readable meter borrows an idea from real audio equipment: a
horizontal strip that shifts color from a calm dark grey up through
to an alarming bright red as level increases, with a large numeric
readout for the precise value. The approved widget palette has no
single widget that paints a gradient — but nothing stops you from
building one out of **many small `M5LED` widgets placed side by
side**, each one a fixed step along a dark-grey-to-red interpolation.

This is a genuinely new construction technique: every widget you've
built so far has been **one widget, one job**. A gradient meter is
**many widgets, one combined visual effect** — the segments don't
move or change color once built; what changes is *how many of them
are lit* as the sound level rises and falls.

**Step 1 — Precompute each segment's color, once, in `setup()`.**
Interpolating between two RGB888 colors is a linear blend, per
channel, exactly like every other clamp-and-scale formula this course
has used — just applied three times (red, green, blue) instead of
once:

```python
DARK_GREY = (0x40, 0x40, 0x40)
BRIGHT_RED = (0xFF, 0x00, 0x00)

def lerp_color(t, c_low, c_high):
    r = int(c_low[0] + (c_high[0] - c_low[0]) * t)
    g = int(c_low[1] + (c_high[1] - c_low[1]) * t)
    b = int(c_low[2] + (c_high[2] - c_low[2]) * t)
    return (r << 16) | (g << 8) | b
```

`t` is a 0.0–1.0 fraction — the same "how far along the range" idea
as `fraction` in every clamp-and-scale formula so far. `t=0.0` gives
pure dark grey, `t=1.0` gives pure bright red, and anything between
blends smoothly.

**Step 2 — Build a row of small `M5LED` segments, one per step, each
initialized to its own point along the gradient:**

```python
SEGMENT_COUNT = 20
SEGMENT_W = 15   # 20 segments * 15px = 300px, same width as other widgets

segments = []

def build_meter(parent, x, y, h):
    for i in range(SEGMENT_COUNT):
        t = i / (SEGMENT_COUNT - 1)
        seg_color = lerp_color(t, DARK_GREY, BRIGHT_RED)
        seg = m5ui.M5LED(
            x=x + i * SEGMENT_W, y=y,
            size=h, color=seg_color, on=True,
            parent=parent,
        )
        seg.set_brightness(15)   # dim "off" look until lit
        segments.append(seg)
```

Each segment is a small square `M5LED` — `size=h` makes it exactly
`h` pixels wide *and* tall, which is what makes a **short, several-
pixel-high strip** rather than a row of large circles. A `size` of
roughly 12–18 gives a slim bar-like strip without the segments
touching or overlapping (`SEGMENT_W=15` leaves no gap and no overlap
for a `size` up to `15`).

**Step 3 — Light segments up to the current level, every `loop()`
pass, and dim the rest.** This is the same "how many, not what color"
idea real VU meters use — the color of each segment never changes
after `setup()`; only how bright it appears does:

```python
def update_meter(percent):
    lit_count = int((percent / 100) * SEGMENT_COUNT)
    for i, seg in enumerate(segments):
        if i < lit_count:
            seg.set_brightness(100)
        else:
            seg.set_brightness(15)
```

`lit_count` is one more clamp-and-scale-shaped conversion: a 0–100
percentage mapped onto a 0–`SEGMENT_COUNT` count of lit segments. At
`percent=0`, no segments light beyond their dim "off" look; at
`percent=100`, all twenty light fully, and the strip reads as a solid
grey-to-red gradient at full brightness.

> **Why not just recolor one wide `M5LED` instead of using twenty
> small ones?** A single widget has exactly one `color` at a time —
> recoloring it as level changes would show *only the color for the
> current level*, not the gradient scale itself. The whole point of
> the segmented strip is that the viewer can see the **entire
> grey-to-red range** at a glance, with the lit portion showing where
> the current level sits *within* that range — information a single
> recoloring widget cannot show on its own.

**Step 4 — Pair the strip with a large numeric readout.** The segment
strip shows level at a glance; a big `M5Label` gives the precise
number, using a larger font than this course's other value labels for
quick readability from across a room:

```python
level_number = m5ui.M5Label(
    "0", x=140, y=70,
    text_c=0x000000, bg_c=0xFFFFFF, bg_opa=0,
    font=getattr(lv, "font_montserrat_44", lv.font_montserrat_14),
    parent=page0,
)
```

Updating it is exactly the same `set_text()` call you've used since
Lecture 3 — the only thing new is choosing a large font for
readability, using the `hasattr`/`getattr` fallback from the Available
Fonts section in case a smaller firmware build doesn't include
`font_montserrat_44`.

> **Gotcha — twenty extra widgets is twenty extra objects for
> `loop()` to touch.** Updating twenty `M5LED` segments every pass is
> still cheap compared to the microphone recording itself, but it's
> not free. If you extend this pattern to a much longer strip in your
> own project work, keep the per-pass work per segment to a single
> `set_brightness()` call, exactly as shown above — anything heavier,
> repeated twenty-plus times a loop, starts to add up.

### 8. Worked Example — Sound Level Meter

This ties the lecture together: a continuously-updating `M5LED` and a
grey-to-red **gradient meter with a large numeric readout**, both
driven by ambient sound level, plus a mode switch that changes
sensitivity — the same **poll-driven sensor + event-driven switch**
combination Lecture 4 introduced with the tilt bar and calibration
switch.

```python
# SPDX-License-Identifier: MIT
#
# PRG455 Lecture 7 -- Sound Level Meter
# Demonstrates the microphone (Mic.begin()/record()/isRecording()),
# reducing a raw PCM buffer to a peak amplitude, the clamp-and-scale
# pattern applied to audio, M5LED (continuously updated from loop(),
# like M5Bar in Lecture 4) alongside an event-driven M5Switch, and a
# grey-to-red gradient meter built from a row of small M5LED segments
# with a large numeric readout.

import os, sys, io
import struct
import M5
from M5 import *
import m5ui
import lvgl as lv

ANIM_OFF = getattr(lv, "ANIM_OFF", 0)

page0 = None
title_label = None
led0 = None
percent_label = None
level_number = None
sensitive_switch = None
mode_label = None
segments = []
is_sensitive = False   # flipped in the handler, never read from get_state()

rec_data = None
SAMPLE_RATE = 16000

NORMAL_CEILING = 16000     # peak amplitude treated as "100%" in Normal mode
SENSITIVE_CEILING = 6000   # peak amplitude treated as "100%" in Sensitive mode
NOISE_FLOOR = 200          # peak amplitude treated as "silence" in both modes

SEGMENT_COUNT = 20         # number of small LEDs making up the gradient strip
SEGMENT_W = 15             # 20 segments * 15px = 300px, matching other widgets
DARK_GREY = (0x40, 0x40, 0x40)
BRIGHT_RED = (0xFF, 0x00, 0x00)


def clamp(value, low, high):
    if value < low:
        return low
    if value > high:
        return high
    return value


def peak_amplitude(buf):
    sample_count = len(buf) // 2
    samples = struct.unpack("<%dh" % sample_count, buf)
    peak = 0
    for s in samples:
        if abs(s) > peak:
            peak = abs(s)
    return peak


def amplitude_to_percent(peak, ceiling):
    peak = clamp(peak, NOISE_FLOOR, ceiling)
    fraction = (peak - NOISE_FLOOR) / (ceiling - NOISE_FLOOR)
    return int(fraction * 100)


def lerp_color(t, c_low, c_high):
    # Linear blend between two RGB888 colors, one channel at a time --
    # the same "fraction of the way across a fixed range" idea behind
    # every clamp-and-scale formula so far, applied three times.
    r = int(c_low[0] + (c_high[0] - c_low[0]) * t)
    g = int(c_low[1] + (c_high[1] - c_low[1]) * t)
    b = int(c_low[2] + (c_high[2] - c_low[2]) * t)
    return (r << 16) | (g << 8) | b


def build_meter(parent, x, y, h):
    # Each segment's color is fixed once, here, at its own point along
    # the grey-to-red gradient. Only brightness changes after this.
    for i in range(SEGMENT_COUNT):
        t = i / (SEGMENT_COUNT - 1)
        seg_color = lerp_color(t, DARK_GREY, BRIGHT_RED)
        seg = m5ui.M5LED(
            x=x + i * SEGMENT_W, y=y,
            size=h, color=seg_color, on=True,
            parent=parent,
        )
        seg.set_brightness(15)   # dim "off" look until lit
        segments.append(seg)


def update_meter(percent):
    # How many segments are lit -- not their color -- is what shows
    # the current level; segments below lit_count light fully, the
    # rest stay dim.
    lit_count = int((percent / 100) * SEGMENT_COUNT)
    for i, seg in enumerate(segments):
        if i < lit_count:
            seg.set_brightness(100)
        else:
            seg.set_brightness(15)


def sensitive_switch_changed(event_struct):
    # is_sensitive is FLIPPED here, never read via get_state(). See
    # the confirmed hardware finding earlier in this lecture: on this
    # hardware, M5Switch.get_state() lags on the OFF transition badly
    # enough that even a single read taken right at the OFF event
    # cannot be trusted -- so the handler must never call it at all.
    global is_sensitive
    is_sensitive = not is_sensitive
    if is_sensitive:
        mode_label.set_text("Mode: Sensitive")
    else:
        mode_label.set_text("Mode: Normal")


def sensitive_switch_handler(event_struct):
    if event_struct.code == lv.EVENT.VALUE_CHANGED:
        sensitive_switch_changed(event_struct)
    return


def setup():
    global page0, title_label, led0, percent_label, level_number
    global sensitive_switch, mode_label, rec_data

    M5.begin()
    Widgets.setRotation(1)
    m5ui.init()
    page0 = m5ui.M5Page(bg_c=0xFFFFFF)

    title_font = getattr(lv, "font_montserrat_20", lv.font_montserrat_14)
    title_label = m5ui.M5Label(
        "Sound Level Meter", x=10, y=4,
        text_c=0x000000, bg_c=0xFFFFFF, bg_opa=0,
        font=title_font, parent=page0,
    )

    led0 = m5ui.M5LED(
        x=135, y=32, size=40,
        color=0x2C90E4, on=True, parent=page0,
    )
    led0.set_brightness(0)

    large_font = getattr(lv, "font_montserrat_44", lv.font_montserrat_14)
    level_number = m5ui.M5Label(
        "0", x=150, y=78,
        text_c=0x000000, bg_c=0xFFFFFF, bg_opa=0,
        font=large_font, parent=page0,
    )

    build_meter(page0, x=10, y=140, h=15)

    percent_label = m5ui.M5Label(
        "Level: 0%", x=10, y=162,
        text_c=0x000000, bg_c=0xFFFFFF, bg_opa=0,
        font=lv.font_montserrat_14, parent=page0,
    )

    mode_label = m5ui.M5Label(
        "Mode: Normal", x=10, y=190,
        text_c=0x000000, bg_c=0xFFFFFF, bg_opa=0,
        font=lv.font_montserrat_14, parent=page0,
    )
    sensitive_switch = m5ui.M5Switch(
        x=150, y=188, w=50, h=25,
        parent=page0,
    )
    sensitive_switch.add_event_cb(sensitive_switch_handler, lv.EVENT.ALL, None)

    Mic.begin()
    rec_data = bytearray(1024)

    page0.screen_load()


def loop():
    M5.update()

    Mic.record(rec_data, SAMPLE_RATE, False)
    while Mic.isRecording():
        pass

    # Read from is_sensitive, never sensitive_switch.get_state() --
    # see the note above sensitive_switch_changed().
    ceiling = SENSITIVE_CEILING if is_sensitive else NORMAL_CEILING
    peak = peak_amplitude(rec_data)
    percent = amplitude_to_percent(peak, ceiling)

    led0.set_brightness(percent)
    level_number.set_text(str(percent))
    update_meter(percent)
    percent_label.set_text("Level: %d%%" % percent)

    # A second M5.update() call, after this pass's set_text()/
    # set_brightness() calls, flushes those changes to the screen
    # immediately rather than waiting for the next pass's M5.update()
    # at the top of loop() -- the same fix needed anywhere a widget is
    # updated from inside loop(), called out in §5's original gotcha.
    M5.update()


if __name__ == '__main__':
    try:
        setup()
        while True:
            loop()
    except (Exception, KeyboardInterrupt) as e:
        try:
            m5ui.deinit()
            from utility import print_error_msg
            print_error_msg(e)
        except ImportError:
            print("please update to latest firmware")
```

Notice `percent_label` follows the same rule established in Lecture 4:
any label showing a live sensor-driven value is updated from `loop()`,
right next to the widget it describes — never from an event handler,
since there's no touch event driving it.

### 9. Key Takeaways

- The microphone doesn't hand you a ready-made volume level — you
  **record a short buffer** (`Mic.begin()` → `Mic.record()` →
  `Mic.isRecording()`) and **compute** a number from it yourself.
- Audio samples are **16-bit signed integers**, two bytes each;
  `struct.unpack("<%dh" % n, buf)` is the standard way to turn a raw
  buffer into a tuple of sample values.
- This course always reduces a buffer to its **peak absolute
  amplitude** — the loudest single sample — because it's simpler to
  reason about and won't smooth away short, sharp sounds the way an
  average would.
- **Clamp-and-scale applies again**, exactly as it did for the IMU in
  Lecture 4: pick a `noise_floor` and a `ceiling` empirically on your
  own hardware, clamp the raw peak into that range, then convert to a
  bounded percentage.
- `M5LED` is a **display-only** widget — no `VALUE_CHANGED` event, no
  `add_event_cb` — driven directly from `loop()` via `set_brightness()`,
  `set_color()`, `on()`/`off()`/`toggle()`, the same poll-driven role
  `M5Bar` played in Lecture 4.
- **The mic and speaker share the same I2S hardware and cannot run at
  the same time** — call `Speaker.end()` before `Mic.begin()` in any
  program that uses both (relevant starting next week).
- Keep recording buffers **short**. A `Mic.record()` call blocks for
  roughly `buffer_size / sample_rate` seconds — long enough, at a
  large buffer size, to make both the LED update and any switch on
  screen feel sluggish.
- **Counting discrete sounds (like words) needs state tracked across
  multiple `loop()` passes**, not a single-buffer calculation — a real
  pause is much longer than one buffer, so you track consecutive
  silent passes and only count on the transition *out of* a confirmed
  gap, which naturally avoids double-counting a brief in-word dip.
- A **gradient meter** is built from **many small `M5LED` widgets**,
  each pre-colored once in `setup()` via linear RGB interpolation
  (`lerp_color`) and never recolored again — only *how many* are lit,
  via `set_brightness()`, changes in `loop()`. Pair it with a large-
  font `M5Label` for a precise numeric readout alongside the at-a-
  glance visual.
