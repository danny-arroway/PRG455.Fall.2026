# Week 10 — Major Project: Design, Architecture, and AI-Assisted Planning

**Lecture:** Nov 19 · **Lab:** Nov 16

## Lecture Topic

Major project design, architecture, and AI-assisted planning — the first of two Major Project
weeks. This lecture has no new hardware capability and no new widget; it establishes the
project's fixed requirements, walks through decomposing a project idea into a state model before
any widget code is written, flags the integration risks that appear only once subsystems are
combined, and covers where Claude is (and isn't) useful at the planning stage.

## This Week's Materials

| File | Covers |

## Lab Activity — Project Work Time: Proposal & Design Review

No new build this week. Lab time is spent producing the written project proposal described in
`10.1_major_project_design_and_architecture.md` §7 — purpose statement, subsystem list, state
table, poll-vs-event decision per state entry, rough layout sketch, integration risk check, and
file structure — and reviewing it with your instructor before Week 11 implementation begins.

## Before this lab

Read `10.1_major_project_design_and_architecture.md` in full. Come to the Nov 16 lab with your
three-or-more subsystem choice already made and your state list (§3) started — the lab session is
for refining and reviewing a proposal, not for starting from a blank page.

## Self-check before the design review

- Purpose statement is one paragraph and explains what the app is *for*, not just what it does
- At least three Weeks 3–9 hardware/widget pairings identified, each with a stated reason for
  its inclusion
- State table lists every piece of data the program needs to remember, with its producing
  subsystem noted
- Each state entry marked poll-driven or event-driven, matching the pattern from Lecture 6
- Rough widget layout sketched with approximate coordinates, no unbounded labels overlapping
  other widgets
- All three integration risks (screen space, `loop()` load, overlapping background operations)
  addressed, even if the answer is "not applicable to this design, because..."
- File structure decided — one file or several, and if several, how state is shared
- `PROMPTS.md` started and current if AI assistance was used in scoping or drafting the proposal
